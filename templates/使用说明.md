# 使用说明（人端入口）

## 查询

- **在 Claude Code 会话里直接问**（推荐）：项目根 `CLAUDE.md` 已约定先读 [[index]] 路由到页再回答，细节按「来源:」回仓库验证。
- 在 Obsidian 里：把 `docs/kb/` 作为 vault 打开，用全局搜索 / 图谱视图 / 反链面板；`views/` 下的自动表格由每页 frontmatter 派生，无需维护。

## 新增计划 / 待办，写在哪

| 方式 | 做法 | 适合 |
|------|------|------|
| ① 收集箱（推荐，零负担） | 随手写进 `note.md`（任意节），再对 Claude 说 **「查笔记」** | 想法还不成熟、懒得管格式 |
| ② 直接写库 | 在 `plans/` 新建一页（一页一主题），顶部只放最小 frontmatter | 已经想清楚的正式计划 |

```yaml
---
type: plan
status: active
tags: []
sources: []
updated: {{DATE}}
---
```

两种方式殊途同归：互链、index 登记、log 记账由 Claude 在下次「查笔记」时补齐——**你不必碰 `index.md` 和 `log.md`**。

## 修改已有内容

- **改正文**：直接改，人机皆宜（来源指针别删即可）。
- **改结构**（换页名/增删链接/动 frontmatter/记新坑）：说一句「查笔记」并口述，Claude 改页 + 刷索引 + 记 log。
- 历史决策、踩坑新证据 → 优先补进对应页的「来源事件」，别开新页重复。

## 三个操作循环

- **「查笔记」（= Ingest + Query）**：先蒸馏收集箱、补记本次会话新坑/决策，再回答；无待蒸馏条目时就是纯查询。
- **Query**：也可不喊触发词直接提问，同样先读 `index.md` 路由。
- **Lint**：「自检知识库」——查矛盾/过期计划/孤岛页/frontmatter 缺失。

## 边界

LLM 维护契约（schema）详见本库 `CLAUDE.md`。版本管理走项目 git；`.obsidian/` 不手写也不入库；`sources.md` 登记的源头只读，可写的只有本库各页与 `note.md`。
